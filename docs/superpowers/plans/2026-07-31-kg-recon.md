# KG Recon in Session-Owning Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the four session-owning BuildDown skills consult the project's KG during Phase 1 Orient — advisory, non-blocking, hybrid-search only — with a shared procedure defined once.

**Architecture:** One canonical procedure doc (`docs/kg-recon.md`, mirroring `docs/learnings-comments.md`) holds the whole recon behavior (guard → query → use → staleness-delta → failure-tolerant). Each of `bd-build-up`, `bd-mega-build-up`, `bd-build-down`, `bd-super-build-down` gets a short **titled** step in its Phase 1 Orient that references the doc and supplies skill-specific query inputs. Everything degrades to a silent no-op when the project has no KG.

**Tech Stack:** Markdown skills (`plugin/skills/<name>/SKILL.md`, auto-discovered), the spec #1 `kg.*` CLAUDE.md binding + `kg.search_tool` (`mcp__<slug>-kg__kg_hybrid_search`). No executable code — validation is mechanical.

**Spec:** `docs/superpowers/specs/2026-07-31-kg-recon-design.md`
**Depends on:** spec #1 (the `kg.*` binding, `kg.search_tool`, `docs/kg-binding.md`) — already on this branch.

## Global Constraints

- **Hybrid-search only.** Recon calls **only** `kg.search_tool` (`kg_hybrid_search`), `limit: 8`. Never name/call `kg_search`, `kg_neighbors`, `kg_provenance`, `kg_path`, or `kg_semantic_search`.
- **Advisory & non-blocking.** Recon informs; it never gates planning/triage and never aborts the host skill. No mandatory-citation checklist.
- **Silent skip when no KG.** `kg.present: false` / block absent ⇒ the recon step produces **no output** (it is an *incidental* step — the opposite of the directly-invoked `bd-kg-*` skills). Consistent with `docs/kg-binding.md`.
- **Named step (BDS-29).** In each skill the recon step is a **titled** step in Phase 1 Orient (its own heading/bold label), never buried in prose — so it actually runs.
- **Query as-is.** Recon never rebuilds the graph; refresh stays the operator's `bd-kg-refresh` step.
- **Staleness threshold = 24h.** Always note the KG's age (from the `graph.trig` mtime). Run the "what's new since" delta queries **only if** the KG is older than 24h; a fresher KG skips them.
- **Single source.** The full procedure lives in `docs/kg-recon.md`; the four skills **reference** it and add only their query inputs + placement — they do not restate the procedure.
- **Scope = the four session-owning skills only.** Do not touch `bd-summit-push`, `bd-smoke-jumper`, `bd-belay-on`, `bd-project-setup`, or the spec #1 files.
- **Skill frontmatter is unchanged** by the skill edits (body-only additions).

### Task 1: `docs/kg-recon.md` — the shared recon procedure

**Files:**
- Create: `docs/kg-recon.md`

**Interfaces:**
- Produces: the canonical recon procedure the four skills reference in Tasks 2–3.

- [ ] **Step 1: Write `docs/kg-recon.md`**

The doc must define the procedure in these five parts, with this substance:

1. **Guard.** Read CLAUDE.md's `## Knowledge graph` block (format: `docs/kg-binding.md`). If `kg.present` is false or the block is absent → **skip silently, no output**. (Incidental step — do not announce, unlike the directly-invoked `bd-kg-*` skills.)
2. **Query.** Derive **1–3** short queries from the work in hand (the calling skill supplies the inputs) and call **`kg.search_tool`** with `{query, limit: 8}`. Hybrid-search **only** — never other KG tools.
3. **Use the results.** Surface the top relevant learnings/decisions/issues to the operator as orientation context. Where a hit changes a plan choice or a gap decision, cite it inline (e.g. "prior learning `AII-259` says … so …"). Advisory — no required-citation checklist; if nothing is relevant, say so in one line and move on.
4. **Staleness-delta.** Get the KG's last-build time from the graph file mtime:
   `` stat -f %m "<kg.path>/out/graph.trig" `` (macOS) / `` stat -c %Y … `` (Linux) → compare to now. **Always** note the age in one line. **If older than 24h**, list what the KG is blind to at the standard ingest points:
   - tracker issues updated since that time — via the project's bound tracker MCP (Linear/Jira "updated after <date>");
   - PRs merged since — `gh pr list --state merged --search "merged:>=<YYYY-MM-DD>" --limit 20`.
   Present the gap ("KG last built <age> ago; since then N issues changed, M PRs merged — treat results as missing these") and nudge `bd-kg-refresh`. A KG fresher than 24h → **skip these delta queries** (stay fast).
5. **Failure tolerance.** Any error — tool unavailable, empty index / `degraded: true`, tracker or `gh` hiccup — → note it in one line and **proceed**. Recon never aborts or blocks the host skill.

Also state up top: this procedure is referenced by the four session-owning skills (`bd-build-up`, `bd-mega-build-up`, `bd-build-down`, `bd-super-build-down`) and closes the learnings loop (the skills that post learnings read them here).
